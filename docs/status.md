## Що перевірено про модель

Джерела — **сторонні сторінки, не офіційна картка моделі**. HuggingFace був
недоступний для завантаження під час перевірки. Перед тим, як покладатись на
будь-що з цього, відкрий `huggingface.co/Qwen/Qwen3.8-27B` сам.

| що | значення |
|---|---|
| Ліцензія | Apache 2.0, реліз 14.08.2026 |
| Контекст | 262 144 нативно, до 1M через YaRN |
| VRAM | BF16 ≈ 54 ГБ, 8-біт ≈ 27 ГБ, 4-біт ≈ 14 ГБ |
| Провайдер | OpenRouter: `qwen/qwen3.8-27b-20260814` (датований знімок) |
| Семплінг, thinking | temp 1.0, top_p 0.95, top_k 20 |
| Семплінг, non-thinking | temp 0.7, top_p 0.80, top_k 20, presence_penalty 1.5 |

### Знахідка, яка змінює три фази плану

**Thinking увімкнений за замовчуванням, `reasoning_effort` = `xhigh`,
`preserve_thinking` теж увімкнений.** Міркування приходять окремим полем
`reasoning_content`, не в `content`.

- **Фаза 1.** Клієнт мусить явно обробляти `reasoning_content`, інакше воно
  загубиться або потрапить у `content` як сміття. У плані цього немає.
- **Фаза 5.** `preserve_thinking` тягне блоки міркувань попередніх кроків у
  контекст. Він росте значно швидше, ніж передбачає розрахунок бюджету.
- **Фаза 9.** Вартість. За цінами одного з провайдерів ($0.58 вхід /
  $3.45 вихід за 1M) агентна задача з `xhigh` з'їдає близько 50K вхідних і
  30K вихідних токенів ≈ $0.13. Тисяча траєкторій ≈ $130. З вимкненим
  міркуванням вихід падає разів у шість → ≈ $50. Одне налаштування дає
  дво-трикратну різницю в бюджеті фази.

Вмикати міркування чи ні — **вимірюється, а не вгадується**: для coding-агента
воно може реально допомагати.

### Друга правка до плану: фаза 9 має йти на орендовану GPU, не в API

Генерація траєкторій — пакетна робота, яка насичує карту повністю.

    API:    30M вихідних токенів × $3.45/1M                      ≈ $103
    Оренда: 48 ГБ × $0.60/год, vLLM з батчингом, ~8 год          ≈ $5–10

Різниця на порядок. План відправляє фазу 9 в API.

### Чого ще не знаємо

- **Формат tool calls у chat template.** Менш терміново, ніж здавалось: через
  OpenRouter усе йде в OpenAI-сумісному форматі незалежно від рідного шаблону.
  Рідний шаблон стає важливим аж у фазі 11 (власний vLLM).
- **Чи є окремий Instruct-варіант.** Base-модель у tool-use циклі не працюватиме.
- **Commit hash ревізії** на HuggingFace.

### Стратегія витрат: безкоштовно скільки можливо

Фази 0–8 — harness, інструменти, sandbox, permissions, evals, RAG, MCP,
безпека — розробляються проти **`qwen2.5:3b-instruct-q4_K_M` в Ollama локально**
за нуль грошей. Це не компроміс, а сенс model-agnostic дизайну.

27B потрібна рівно в трьох місцях: базові числа на evals (фаза 3), генерація
траєкторій (фаза 9), дотренування (фаза 10).

Перевірено 2026-11-07: tool calling на цій моделі через
`http://localhost:11434/v1/chat/completions` **працює** — повертає
`finish_reason: "tool_calls"`, правильний інструмент і аргументи.

Два факти з тієї відповіді: `usage` **не має** лічильника reasoning-токенів
(qwen2.5 не має режиму думання — облік має бути готовий до появи поля на 27B),
і `system_fingerprint` = `fp_ollama`, тобто справжньої ревізії Ollama не
повертає, пінити доведеться тегом у конфізі.

### Залізо

7 ГБ RAM, ~2 доступно, немає дискретної GPU, 12 потоків.
IDE + Ollama + Docker на 7 ГБ не вживуться — на час прогонів агента IDE
доведеться закривати.
